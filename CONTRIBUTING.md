# Contributing to Certiv projects

Thank you for helping improve a Certiv project.

Before contributing:

1. Read the target repository's README, support policy, and local contribution
   guide. Repository-specific guidance overrides this default.
2. Search existing issues and discussions before opening a duplicate.
3. Keep bug reports reproducible and free of credentials, customer data, or
   other sensitive information.
4. Use the private process described in `SECURITY.md` for vulnerabilities.

For code changes:

- explain the concrete user problem;
- keep the change focused;
- add or update tests;
- update user-facing documentation;
- run the repository's documented validation commands;
- disclose new dependencies, network behavior, telemetry, or data handling.

Repository maintainers will state whether a project currently accepts external
contributions. An open repository does not automatically imply a support or
merge commitment.
